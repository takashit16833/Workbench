# BR-0006 アプリケーション実行を機能処理結果とログ出力結果から合成する

> [!warning] 非正本
> このIdeaは現在仕様そのものではありません。正本と矛盾する場合は正本を優先します。

## 次のレビュー

**条件:** RS-0015/output-boundariesへ実行結果合成を実装する前

**判断すること**

- `AppError`と`LoggingFailure`を独立した失敗軸として保持するか
- 「何が起きたか」を直積で表し、「アプリケーションとして何を意味するか」を直和で解釈する二段構造を採用するか
- アプリケーション全体の線形な処理を`AppAction`で合成するか
- `ExceptT AppError IO a`を個々の機能処理用として残す必要があるか、それとも型エイリアス自体が不要か
- 最終結果に専用の`ExecutionResult`を設けるか、`Either ExecutionFailure a`で十分か

## 背景

現在の`AppResult a = ExceptT AppError IO a`は、機能処理の失敗である`AppError`だけを短絡できる。

一方、実際のアプリケーション処理では、文書読み込み、文書パースなどの各処理結果を確定した境界でログを出力する。機能処理が成功してもログ出力が失敗する場合があり、`LoggingFailure`を`AppError`へ変換すると、両者を区別する現在の要求を型で表せない。

そのため、機能処理の結果とログ出力の結果を一度独立した事実として保持し、その組み合わせをアプリケーション実行上の意味へ解釈する案を検討する。

## 現在の案

### 事実を直積で保持する

```haskell
data ExecutionOutcome a = ExecutionOutcome
  { featureResult :: Either AppError a
  , loggingResult :: Either LoggingFailure ()
  }
```

`ExecutionOutcome`はアプリケーションの最終的な成功・失敗ではなく、1つの観測境界で機能処理とログ出力に何が起きたかを保持する。

| 機能処理 | ログ出力 | 事実 |
|---|---|---|
| 成功 | 成功 | `Right a` / `Right ()` |
| 成功 | 失敗 | `Right a` / `Left LoggingFailure` |
| 失敗 | 成功 | `Left AppError` / `Right ()` |
| 失敗 | 失敗 | `Left AppError` / `Left LoggingFailure` |

### 意味を直和で表す

失敗側は次の形を候補とする。

```haskell
data ExecutionFailure
  = LoggingFailed LoggingFailure
  | FeatureFailed AppError
  | FeatureAndLoggingFailed AppError LoggingFailure
```

これにより、機能失敗とログ失敗を別の値として保持し、両方が失敗した場合も元の`AppError`を失わない。

`ExecutionOutcome a`からアプリケーション上の意味へ変換する純粋関数を設ける候補とする。

```haskell
interpretOutcome
  :: ExecutionOutcome a
  -> Either ExecutionFailure a
```

対応は次のとおり。

```text
Right a       × Right ()             -> Right a
Right _       × Left loggingFailure  -> Left (LoggingFailed loggingFailure)
Left appError × Right ()             -> Left (FeatureFailed appError)
Left appError × Left loggingFailure  -> Left (FeatureAndLoggingFailed appError loggingFailure)
```

### アプリケーション全体を`AppAction`で合成する

候補:

```haskell
type AppAction a = ExceptT ExecutionFailure IO a
```

文書処理などのアプリケーションフローでは、機能処理とその観測ログを組み合わせた単位を`AppAction`へ持ち上げ、`>>=`で線形に合成する。

```text
機能処理
  ↓
Either AppError a
  +
ログ出力
  ↓
Either LoggingFailure ()
  ↓
ExecutionOutcome a
  ↓ interpretOutcome
Either ExecutionFailure a
  ↓
AppActionで次の処理へ接続
```

`ExceptT AppError IO a`を`FeatureAction`などの名前で残す場合も、大きな機能フローを別に`>>=`で構成するためには使わない。個々の機能処理を表す型として実際に価値があるかをレビューで判断する。

### 最終結果型は未確定

次の専用型を置く案がある。

```haskell
data ExecutionResult a
  = Succeeded a
  | Failed ExecutionFailure
```

一方、`runExceptT`で得られる`Either ExecutionFailure a`と情報が重複するため、専用の`ExecutionResult`を設ける意味があるかはレビューで決定する。
