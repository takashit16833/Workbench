# ステップ20：最終検証と完了条件照合

Step 15〜19までの変更をまとめて検証し、RS-0015の完了条件を「実装したつもり」ではなく、コード・テスト・Schema・設計・実行結果の証拠と1項目ずつ照合する。

## やること

- RAGScopeリポジトリの最新作業ブランチと`main`、変更差分を確認する
- リポジトリルートから`make check`を実行する
- `make check`に含まれるformat check、`cabal build all`、`cabal test all`、`cabal haddock all`がすべて成功することを確認する
- RS-0015の完了条件を上から1項目ずつ読み、どのコード・テスト・Schema・fixture・設計・代表実行によって満たしているか照合する
- 共通エラー型、Logger初期化、Schema適合、出力失敗、stdout / stderr分離、情報保護など主要な完了条件に検証漏れがないか確認する
- `エラー設計.md`、`構造化ログ設計.md`、Haskell実装、JSON Schema、テストの間に解消していない差異がないか確認する
- 実装で具体化・変更した現在設計が正本へ反映されているか確認する
- Git差分を確認し、RS-0015と無関係な変更を今回の実装変更として混入させていないことを確認する
- 実行できなかった検証や残る制約があれば、完了扱いにせず理由を明示する

## 判定方法

各完了条件は、必要に応じて次の証拠へ対応付ける。

- 型・実装
- 自動テスト
- JSON Schema / fixture
- 現在設計
- 代表的な実行結果

テストがgreenという理由だけでRS-0015全体を完了扱いにしない。

## 完了の目安

- `make check`が成功している
- RS-0015の全完了条件について、満たしている根拠を説明できる
- 未確認の完了条件や重大な設計・実装差異が残っていない
- 失敗した検証を成功扱いしていない
- 変更差分が意図した範囲に収まっている
- Step 21でTicket結果とPR準備へ進める状態になっている

完了条件を満たしていない項目が見つかった場合は、このStep内で無理に帳尻を合わせず、該当するStepへ戻って実装・設計・テストを修正する。
