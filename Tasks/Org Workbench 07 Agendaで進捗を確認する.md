# Agenda で最低限の進捗を確認する

## 完成イメージ

**Emacs の `M-x org-agenda` から、Workbench のタスクについて「今日何をするか」「期限が迫っている・過ぎているものは何か」「進行中・待機中の作業は何か」を確認できる**ようにする。確認するだけでなく、Agenda からタスクを開いて状態を変更し、更新後の状態を再表示できる。

タスク06の Project 別・親別一覧は「所属や階層を手掛かりに目的のタスクを探す」機能。こちらは **予定・期限・状態を手掛かりに、日々の進捗を確認する画面**。新しい Dashboard を一から作るのではなく、Org 標準の Agenda を利用する。以下は表示したい情報を説明する例で、Agenda の正確な画面レイアウトや操作キーを確定するものではない。

### 操作例①：今日の予定と期限を確認する

1. RAGScope の親タスクと、その下の「SQL の実行計画を調べる」に予定や期限を設定しておく。
2. `M-x org-agenda` から今日の予定を確認する。
3. 親タスクだけでなく、日時を指定した子・孫タスクも確認できる。
4. 期限間近・期限超過のタスクも確認し、対応すべき見出しを開く。

例えば、タスクのデータが次の状態だとする。

```org
* TODO API の性能を改善する :p_ragscope:
DEADLINE: <2026-09-25 Fri>

** DOING SQL の実行計画を調べる
SCHEDULED: <2026-09-22 Tue>

*** TODO 遅いクエリを確認する
DEADLINE: <2026-09-21 Mon>
```

2026-09-22 に確認したとき、少なくとも次の情報を探せる状態を目指す。

```text
今日の予定 : SQL の実行計画を調べる（DOING）
期限超過   : 遅いクエリを確認する（TODO / 期限 9月21日）
今後の期限 : API の性能を改善する（TODO / 期限 9月25日）
```

「今後の期限」の表示範囲など、具体的な Agenda の見せ方は実装時に決める。上の3行は同じ画面に必ず同時表示するという意味ではない。

### 操作例②：Agenda から状態を更新する

1. Agenda で「SQL の実行計画を調べる」を選び、元の Org 見出しを開く。
2. 状態を `DOING` から `DONE` に変更して保存する。
3. Agenda を更新すると、進行中の一覧から外れ、未完了の一覧にも残らない。
4. 別の `WAITING` タスクは `TODO` に戻すと、その変更が保存・表示に反映される。

```text
変更前 : DOING   SQL の実行計画を調べる
変更後 : DONE    SQL の実行計画を調べる

変更前 : WAITING 表示速度を計測する
変更後 : TODO    表示速度を計測する
```

`DONE` と `DROPPED` はどちらも未完了タスクの一覧から除外する。完了・中止の日時 `CLOSED` は既存の Org 設定に従って記録する。状態変更には Org の通常の操作を優先し、専用の状態管理画面は作らない。

### 操作例③：新規作成・再起動後も同じタスクを扱う

タスク04・05の Capture で `tasks/` にタスクを追加したら、手動でファイル一覧を書き換えなくても Agenda の検索対象となる。子タスクの `SCHEDULED` / `DEADLINE` も拾う。Emacs を再起動しても対象が失われず、登録漏れや同じタスクの重複表示によって状況を誤認しない。

**このタスクの範囲は、初回リリースに必要な Agenda の検索対象・表示・状態更新の整備まで。** 独自 Dashboard の作り込み、Pomodoro による時間計測、ガントチャートなどは対象外。上記は完成予定の動作例であり、現時点で実装済みという意味ではない。

## やること

`org-agenda` を初回リリースの進捗画面にする。Dashboard を新規で作り込む必要はない。

- Workbench 配下のタスクを Agenda 対象に登録し、新しく Capture したファイルも反映されるようにする。
- 今日の予定、期限間近・超過、未完了のタスク、DOING・WAITING を確認できる表示を整える。
- Agenda 上からタスクを開き、状態変更して表示を更新できる。通常の Org 操作を優先する。
- DONE / DROPPED の扱いを整理し、完了したタスクが未完了一覧に残らないようにする。

## 完了条件

- SCHEDULED / DEADLINE を付けたサブタスクまで Agenda に表示される。
- TODO → DOING → DONE、WAITING → TODO の変更が保存・表示に反映される。
- 起動し直しても同じタスク群を確認でき、登録漏れ・重複で進捗を誤認しない。
