# Project 別とタスク配下の一覧を作る

## 完成イメージ

タスクの保存先ファイルを一つずつ開かなくても、**Project を選んで所属タスクを探す**、または **親タスクを選んでその配下だけを探す** という2種類の一覧を使えるようにする。一覧にはタスクの状態を表示し、目的の項目を選ぶと元の Org ファイルの該当見出しへ移動できる。

Kanban 画面の再現や独自の大きな Dashboard は作らない。Org 標準の検索・見出し構造と既存の Consult などを活用する。以下の一覧は、表示したい情報の例であり、画面デザインやキー操作を確定するものではない。

### 操作例①：RAGScope のタスクをまとめて探す

1. Workbench の Project 別タスク一覧を実行する。
2. 登録済み Project から「RAGScope」を選ぶ。
3. RAGScope 所属の親タスク・子タスクが状態付きで表示される。
4. 例えば「SQL の実行計画を調べる」を選ぶと、保存元の Org ファイルが開き、その見出しへ移動する。
5. 同じ操作で「Workbench」に切り替えたり、無所属のタスクを探したりできる。

一覧の表示内容は、例えば次のイメージ。

```text
Project: RAGScope

TODO     API の性能を改善する
DOING      SQL の実行計画を調べる
TODO     検索画面を改善する
WAITING    表示速度を計測する
```

親の `:p_ragscope:` タグを継承した子孫も、RAGScope の検索結果に含める。子自身に `:p_workbench:` が付いている場合、その子は Workbench の一覧にも現れる。複数所属をどちらか一方に限定しない。

### 操作例②：選んだ親の直下と子孫を見分ける

例えば、ファイルに次の見出しがあるとする。

```org
* TODO API の性能を改善する :p_ragscope:
** DOING SQL の実行計画を調べる
*** TODO 遅いクエリを確認する
** TODO 計測結果をまとめる

* TODO 検索画面を改善する :p_ragscope:
** WAITING 表示速度を計測する
```

親として「API の性能を改善する」を選択すると、確認範囲を切り替えられる。

```text
【直属の子だけ】
DOING  SQL の実行計画を調べる
TODO   計測結果をまとめる

【子孫すべて】
DOING  SQL の実行計画を調べる
TODO     遅いクエリを確認する
TODO   計測結果をまとめる
```

後者には孫の「遅いクエリを確認する」も含まれる。一方、同じ Project に所属する別の親「検索画面を改善する」とその子は混ぜない。直下・子孫のどちらの一覧からも、選んだ子や孫の見出しへ直接移動できる。

### 今回の作業と範囲

Project の登録情報・所属タグ・継承したタグを使ってタスクを収集し、状態付きの検索候補にする。親を選んだ場合は見出しの階層から直属の子と子孫を区別し、選択した見出しへ移動できるようにする。親子の表示重複や並びは見失わない範囲で整理し、UI の作り込みは最小限にする。

**このタスクで作るのは、所属別・親別のタスク検索と一覧表示まで。** 今日の予定や期限をまとめて確認し、Agenda で進捗を操作する機能はタスク07で扱う。上記は完成予定の動作例であり、現時点で実装済みという意味ではない。

## やること

Kanban の再現はせず、Org 標準の検索・Agenda と見出し構造を使って必要な作業を探せるようにする。

- 登録済み Project を選ぶと、所属するタスクを状態付きで一覧表示し、対象の Org 見出しへ移動できる。
- 親から継承した所属や複数 Project への所属も検索結果に含める。無所属を扱えるようにする。
- タスクを選ぶと直属の子タスク、または子孫すべてを確認でき、目的の見出しへ移動できる。
- 親タスクと子タスクが一覧に出る場合の表示重複・並びは、使いやすく最小限の実装にする。既存の Consult 等を活用し、独自 UI は増やしすぎない。

## 完了条件

- RAGScope と Workbench を切り替えてタスク一覧を表示できる。
- 親を選んで直下と子孫を確認できる。サブタスクを直接開ける。
- Project に所属する親の子も表示され、複数所属のタスクを失わない。
