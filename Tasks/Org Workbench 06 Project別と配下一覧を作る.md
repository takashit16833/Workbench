# Project 別とタスク配下の一覧を作る

## 完成イメージ

タスクの保存先ファイルを一つずつ開かなくても、**Project を選んで所属タスクを探す**、または**特定の親を選んでその配下だけを見る**という2種類の一覧を使えるようにする。検索結果に状態を表示し、選んだタスクの Org 見出しへ直接移動できる。

Kanban の画面を再現するのではなく、Org 標準の検索・見出し構造と既存の Consult などを活用する。以下は表示内容の例であり、一覧の見た目や操作キーを確定するものではない。

### 操作例①：Project 全体のタスクを探す

1. Workbench の Project 別一覧を実行する。
2. 登録済み Project から `RAGScope` を選ぶ。
3. RAGScope に所属するタスクが状態付きで並ぶ。目的のタスクを選ぶと、保存元ファイルの該当見出しが開く。
4. 同じ操作で `Workbench` に切り替えられる。無所属タスクも探せる。

例えば、別々の親タスクが RAGScope に所属している場合、一覧の内容は次のイメージになる。

```text
Project: RAGScope

TODO   API の性能を改善する
DOING    SQL の実行計画を調べる
TODO   検索画面を改善する
WAITING   表示速度を計測する
```

親の `:p_ragscope:` を継承した子孫も検索対象にする。子に `:p_workbench:` が追加されていれば、同じ子は Workbench の一覧にも現れる。所属を一つに限定したり、タグを子に重複保存したりしない。

### 操作例②：選んだ親の配下だけを見る

例えば次のように、RAGScope 内に2つの親タスクがあるとする。

```org
* TODO API の性能を改善する :p_ragscope:
** DOING SQL の実行計画を調べる
*** TODO 遅いクエリを確認する
** TODO 計測結果をまとめる

* TODO 検索画面を改善する :p_ragscope:
** WAITING 表示速度を計測する
```

親に「API の性能を改善する」を選んだとき、2つの見方を切り替えられるようにする。

```text
【直下の子だけ】
DOING SQL の実行計画を調べる
TODO  計測結果をまとめる

【選んだ親と子孫すべて】
TODO    API の性能を改善する
DOING     SQL の実行計画を調べる
TODO        遅いクエリを確認する
TODO      計測結果をまとめる
```

ここでは、同じ RAGScope に属する別の親「検索画面を改善する」とその子は混ぜない。つまり、**Project 別一覧は所属で探すもの、親別一覧は選んだ親の階層に限定して探すもの**。結果から子・孫の見出しも直接開ける。

### 今回の範囲

扱うのは、所属・親子関係に基づく検索と一覧、状態表示、見出しへの移動。親と子が同じ一覧に出るときの並びや重複は読みやすく整理するが、独自の大きな画面は作らない。今日の予定、期限、状態変更をまとめて扱う Agenda の進捗画面はタスク07で整える。

上記は完成予定の操作例であり、現時点ですべて実装済みという意味ではない。

## やること

Kanban の再現はせず、Org 標準の検索・Agenda と見出し構造を使って必要な作業を探せるようにする。

- 登録済み Project を選ぶと、所属するタスクを状態付きで一覧表示し、対象の Org 見出しへ移動できる。
- 親から継承した所属や複数 Project への所属も検索結果に含める。無所属を扱えるようにする。
- タスクを選ぶと直属の子タスク、または子孫すべてを確認でき、目的の見出しへ移動できる。
- 親タスクと子タスクが一覧に出る場合の表示重複・並びは、使いやすく最小限の実装にする。既存の Consult 等を活用し、独自 UI は増やしすぎない。

## 完了条件

- RAGScope と Workbench を切り替えてタスク一覧を表示できる。
- 親を選んで直下と子孫を確認できる。サブタスクを直接開ける。
- Project に所属する親の子も表示され、複数所属のタスクを失わない。
