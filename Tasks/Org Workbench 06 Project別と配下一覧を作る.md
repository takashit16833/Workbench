# Project 別タスク検索・選択を作る

## 完成イメージ

タスクの保存先ファイルを一つずつ開かなくても、**登録済み Project または無所属を選び、その所属タスクを検索・選択できる** ようにする。

Project を選ぶと、その Project に所属する親・子・孫の見出しを一つの候補群として扱う。一覧では TODO 状態と階層が分かるように表示し、目的のタスクを選択できるようにする。

Project とタスクを選ぶ処理は Workbench の共通機能として分離する。Task 06 では、選択したタスクの保存元 Org ファイルを開き、その見出しへ移動する操作を最初の利用先とする。将来は同じ選択処理を org-pomodoro の対象選択などからも再利用できるようにする。

Org Agenda は Workbench 機能の共通の入口として利用できるようにする。ただし Project とタスクの検索・選択機能自体は Agenda に依存させず、必要に応じて単独のコマンドからも利用できるようにする。キー操作の詳細は既存の割り当てを確認して実装時に決める。

Kanban 画面の再現や独自の大きな Dashboard は作らない。既存の completing-read や Consult などを活用し、UI の作り込みは最小限にする。

### 操作例：RAGScope のタスクを探す

1. Org Agenda などから Workbench の Project タスク検索を実行する。単独のコマンドから実行してもよい。
2. 登録済み Project または無所属から「RAGScope」を選ぶ。
3. RAGScope に所属する親・子・孫のタスクが、状態と階層が分かる形で表示される。
4. 候補を検索し、「SQL の実行計画を調べる」を選ぶ。
5. 保存元の Org ファイルが開き、その見出しへ移動する。

一覧の表示内容は、例えば次のイメージ。

```text
Project: RAGScope

TODO     API の性能を改善する
DOING      SQL の実行計画を調べる
TODO         遅いクエリを確認する
TODO       計測結果をまとめる
TODO     検索画面を改善する
WAITING    表示速度を計測する
```

親の `:p_ragscope:` タグを継承した子孫も RAGScope の検索結果に含める。子自身に `:p_workbench:` が付いている場合、その子は Workbench の一覧にも現れる。複数所属をどちらか一方に限定しない。

継承込みの有効タグに登録済み Project のタグを一つも持たない見出しは、無所属として検索できるようにする。

### 共通のタスク選択

Project とタスクの選択までを共通処理とし、その後の操作と分離する。

```text
Project を選択
        ↓
所属タスクを検索・選択
        ↓
選択した見出し情報を利用
        ├─ Org 見出しを開く
        └─ 将来: org-pomodoro の対象にするなど
```

Task 06 では Org 見出しを開くところまでを扱う。Pomodoro の対象保持や時間計測そのものはこのタスクでは実装しない。

親タスクを別途選び、「直属の子だけ」「子孫すべて」を切り替える操作は初期要件に入れない。親・子・孫は Project の所属タスク一覧の中で階層が分かるように表示する。

### 今回の作業と範囲

Project の登録情報と、各見出しの Org 標準のタグ継承を含む有効タグを照合して所属を判定する。

親の Project タグを継承した子孫は、見出し自身に Project タグが書かれていなくても所属タスクとして扱う。子自身に別の Project タグがある場合は複数 Project に所属できる。

共通の見出し収集では、一覧表示・所属判定・移動に必要な情報を取得する。少なくとも TODO 状態、有効タグ、見出しレベル、元ファイル、位置、outline path を利用する。

**このタスクで作るのは、Project または無所属からタスクを検索・選択し、選択した Org 見出しへ移動するところまで。** 今日の予定や期限、Agenda での進捗操作は Task 07 で扱う。

## やること

- 登録済み Project または無所属を選択できるようにする。
- Project 所属は Org のタグ継承を含む有効な Project タグで判定する。
- 親から継承した所属や複数 Project への所属も検索結果に含める。
- 選択した Project に所属する親・子・孫のタスクを、TODO 状態と階層が分かる形で検索候補にする。
- Project 選択とタスク選択の処理を、選択後の操作から分離して再利用できるようにする。
- 最初の利用先として、選択したタスクの Org ファイルを開き、その見出しへ移動できるようにする。
- Org Agenda から共通の入口として呼び出せるようにする一方、検索・選択機能自体は Agenda に依存させない。
- 既存の completing-read や Consult 等を活用し、独自 UI は増やしすぎない。

## 完了条件

- RAGScope、Workbench、無所属を切り替えてタスクを検索できる。
- Project に所属する親・子・孫が、状態と階層が分かる形で同じ検索候補に表示される。
- 親の Project タグを継承した子孫や、複数 Project に所属するタスクを失わない。
- 継承込みで Project タグを持たない見出しを無所属として検索できる。
- タスクを選択すると、保存元の Org ファイルが開き、その見出しへ移動する。
- Project とタスクの選択処理を、将来ほかの機能から再利用できる構造になっている。
