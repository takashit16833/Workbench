# サブタスクを Capture で直接作成する

## 完成イメージ

Emacs の Capture から既存のタスクや整理用見出しを検索して親に指定すると、**その親の直下に子タスクを追加できる**ようにする。タスクを細分化したいときに、親の Org ファイルを手作業で探し、見出しを追加する必要がなくなる。親が子タスクであっても、さらにその下に孫タスクを作れる。

親のない主タスクを新しい `.org` ファイルに保存するのはタスク04の機能。今回は**既存ファイル内に見出しを増やす**機能を作る。

### 操作例：RAGScope のタスクを細分化する

1. Capture から「Workbench: サブタスク作成」（名称は操作例）を選ぶ。
2. 既存タスクを検索し、親として「API の性能を改善する」を選ぶ。検索結果から対象のファイル・見出しを区別できるようにする。
3. タイトル「SQL の実行計画を調べる」を入力する。必要なら日時や Project も指定し、本文にメモを書く。
4. 確定すると、選んだ親の直下に見出しが追加される。さらに「SQL の実行計画を調べる」を親に選べば、孫タスクも作れる。

例えば元のファイルが次の状態だった場合、

```org
* TODO API の性能を改善する :p_ragscope:
:PROPERTIES:
:ID:       parent-id
:END:

性能改善の方針を整理する。

** TODO API の計測を行う
```

「SQL の実行計画を調べる」を追加したあとのイメージは次のとおり。

```org
* TODO API の性能を改善する :p_ragscope:
:PROPERTIES:
:ID:       parent-id
:END:

性能改善の方針を整理する。

** TODO API の計測を行う

** TODO SQL の実行計画を調べる
:PROPERTIES:
:ID:       child-id
:CREATED:  [2026-09-22 Tue 11:00]
:END:

実行時間とボトルネックを確認する。
```

※ ID・日時・本文は説明用の例。実際の ID は Org の仕組みで一意に生成する。子タスクは親の `:p_ragscope:` をタグ継承で受け取るため、同じタグを子の見出しに重複記述する必要はない。子に `:p_workbench:` を追加すれば、子とその子孫は両方の Project に所属する。

### 操作例：雑用ファイルに小さなタスクを追加する

TODO のない「雑用」という整理用見出しも親に選べる。例えば `雑用.org` が次のようになっている場合、

```org
* 雑用
```

「牛乳を買う」を追加すると、同じファイル内で次の形になる。

```org
* 雑用

** TODO 牛乳を買う
:PROPERTIES:
:ID:       child-id
:CREATED:  [2026-09-22 Tue 11:00]
:END:
```

`牛乳を買う.org` という独立ファイルは作らない。タイトルだけでも追加でき、親が TODO かどうかは問わない。

### 保存・キャンセル時の扱い

既存の親見出しのタイトル・本文・ID、すでにある兄弟タスクを保持したまま、選んだ親の下に新しい見出しだけを追加する。子・孫それぞれの ID は異なる。キャンセルした場合は子見出しを残さず、保存して Emacs を再起動した後も階層を保持する。

**このタスクでは子タスクの作成までを扱う。** Project 単位や特定の親配下の一覧表示はタスク06で作る。上記は完成予定の操作例であり、現時点で実装済みという意味ではない。

## やること

タスクを検索して親を選び、その直下に新しい見出しを追加する。子を独立ファイルにする必要はない。

- ID またはファイル位置から既存タスクを補完検索し、任意の深さの見出しを親に選べるようにする。
- Capture の入力はタイトルだけでもよく、状態・ID・CREATED を自動設定する。日時や Project の追加は必要に応じて指定できる。
- 子は親の所属 Project を継承し、子に別 Project を追加できる。親の見出し・本文・兄弟タスク・ID を壊さない。
- 雑用のような TODO なしの整理用見出しも追加先にできる。

## 完了条件

- RAGScope タスクの子と孫を Capture から直接作れる。
- 雑用ファイルの配下に「牛乳を買う」を追加でき、牛乳用の独立ファイルはできない。
- 保存・キャンセル・再起動後も正しい位置と階層を保ち、親子の ID が重複しない。
