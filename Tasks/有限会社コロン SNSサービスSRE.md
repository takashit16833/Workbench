# SNSサービスのSRE

## 概要
会員数1,300万人超の大手マッチングアプリを運営する企業で、SREとしてサービスの信頼性向上、セキュリティ、コスト最適化、システム再構築などを担当する案件。

- 企業: 有限会社コロン
- 大規模SNS / マッチングサービス
- アプリケーション開発寄りの経験に加え、AWS運用、CI/CD、監視、IaCなどを求めるSRE案件

## 主な業務
- セキュリティ対策
  - パスキー・クライアント証明の導入
  - ATP / ACFPの検証・導入
  - 脆弱性診断
- システム構成・ソースコードをAIと統合したナレッジベース整備
- ユーザー生成データのライフサイクル再設計によるコスト最適化
- システム全体の再定義、アーキテクチャ設計、再構築
- DR対策
- IaC化、CI/CD導入
- AWS EoL対応

## 開発環境

- Linux環境でのアプリケーション運用経験

### 必須条件
- ○ AWS環境でのアプリケーション運用・改善: 既存Webアプリの運用・保守経験があり、AWS / Azure環境へのリリース経験もある。ただしAWS基盤の運用を専任で担当したとは言えない。
- ◎ サーバサイド開発: Python、Node.js / JavaScriptの実務経験が十分にある。
- ?: Linux環境でのアプリケーション運用: 経歴書からLinux運用を明確には確認できない。
- ◎ CI/CD: GitHub Actionsによる自動テスト、デプロイ、DBマイグレーション等のパイプライン構築・運用経験がある。
- △ 監視・アラート設計、パフォーマンスチューニング: SQLパフォーマンスチューニング経験はあるが、監視・アラート設計の明確な実務経験は確認できない。

### 歓迎条件・補強材料
- SREとしての肩書き・専任経験はなし。
- 直近案件でTerraform + Google CloudによるIaCを実務で担当しているため、Terraformは強い補強材料。
- 直近案件ではバックエンドエンジニア兼アーキテクトとして、アーキテクチャ設計、CI/CD、インフラまで一貫して担当。
- マイクロサービス構成の実務経験あり。
- RAGScopeでは要求定義・ドメイン設計・システムアーキテクチャまで行っており、システム全体を見て設計する方向性との相性は良い。ただし個人開発であり実務経験には数えない。

### 判断
前の「クラウドサービス構築運用」案件よりも、アプリケーション開発者としての経験を活かしやすい。SRE専任経験、Linux運用、監視・アラート設計が弱点だが、サーバサイド開発、CI/CD、Terraform、運用保守、性能改善で補強できる。

書類通過の確度が高い案件とは言えないものの、今後アーキテクチャやクラウド側へ領域を広げたい志向にも合うため、チャレンジ枠としては応募価値がある。
