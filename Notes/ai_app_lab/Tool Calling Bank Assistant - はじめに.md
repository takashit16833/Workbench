# Tool Calling 銀行アシスタント — はじめに

## このプロジェクトでやりたいこと

**AIに「これをやって」と提案させ、人間が作ったプログラムが安全を確認してから実行する。**

この仕組みを、自分の手で作って理解するのが目標です。

題材は、小さな銀行アシスタント。できることは **残高照会** と **送金** の2つだけです。

銀行アプリを完成させたいわけではありません。「AIが外部の機能を使うとき、どこまでをAIに任せ、どこからをプログラムが責任を持つのか」を学びます。

## どんな仕組みを作るの？

たとえば、ユーザーがこう頼んだとします。

> A001の口座からA002に3000円送って。

完成形では、次の順番で動きます。

```text
あなた「A001からA002に3000円送って」
                  ↓
AI（LLM）「送金機能を、この口座と金額で使おう」
                  ↓
アプリ「本当に送金して大丈夫？」と確認
                  ↓
        ┌─────────┴─────────┐
      問題なし             問題あり
        ↓                    ↓
      送金する             送金しない
        └─────────┬─────────┘
                  ↓
          実行結果をAIに伝える
                  ↓
AI「3000円を送金しました」
  または「残高が不足しています」
```

これが **Tool Calling（関数呼び出し）** の基本的な考え方です。

AIが直接お金を動かすのではありません。AIは「どの機能を、どんな引数で使いたいか」を提案します。**実際に実行してよいか決めるのはアプリ**です。

## 今回作る2つの機能

| 機能 | 何をする？ |
| --- | --- |
| `get_balance` | 指定した口座の残高を調べる |
| `transfer_funds` | ある口座から別の口座へお金を移す |

使う口座は架空の3つです。

| 口座 | 最初の残高 | 状態 |
| --- | ---: | --- |
| A001 | 15,000円 | 利用可能 |
| A002 | 5,000円 | 利用可能 |
| A003 | 0円 | 凍結中 |

A001からA002へ3000円送金できれば、残高はそれぞれ12,000円と8,000円になります。

一方で、残高が足りない、送金額がマイナス、口座が凍結されている、といった場合は**送金せず、残高も変えません**。

## 最初はAIを使わない。それでもTool Callingの学習なの？

**はい。最初は、AIが出すはずの「機能を使いたい」という要求を、手で用意します。**

たとえば次のJSONです。

```json
{
  "name": "transfer_funds",
  "arguments": {
    "source_account_id": "A001",
    "target_account_id": "A002",
    "amount": 3000
  }
}
```

これは「送金機能を使って、A001からA002に3000円移したい」という要求をデータで表したものです。

※ 実際のAIサービスの返答形式そのものではなく、学習しやすいように単純化した内部形式です。

最初にAIをつなげないのは、**AIの判断が間違ったのか、アプリの検証が間違ったのか**を混ぜずに学ぶためです。

ここでは、AIの賢さではなく、**AIが変な要求を出しても、アプリが安全に断れるか**を確かめます。

## 何を試すの？

まず、正しい要求が通ることを確認します。

- 「A001の残高を教えて」→ 15,000円と返る
- 「A001からA002に3000円送って」→ 残高が正しく変わる

次に、困った要求をわざと渡してみます。

- 存在しない機能を指定する
- 送金先を書き忘れる
- 送金額を0円やマイナスにする
- 存在しない口座や凍結口座を使う
- 残高より多い金額を送ろうとする

これらは**失敗したとわかる結果を返し、残高を変えない**ことをテストします。

結果は、人にもプログラムにも扱いやすいよう、成功・失敗をJSONで返します。

## どんな順番で進めるの？

| 段階 | やること | 学べること |
| --- | --- | --- |
| **1. 安全な実行部分を作る** | 手で用意したJSONを検証して、残高照会・送金を動かす | AIの提案を信用せずに扱う方法 |
| **2. AIの返答形式を読み取る** | 実際のAIサービスのTool Callを、アプリで扱う形に変換する | AIとアプリのデータの受け渡し |
| **3. 本物のAIをつなぐ** | 自然言語からAIに機能を選んでもらう | AIがTool Callをどう提案するか |
| **4. 結果をAIに返す** | 実行結果をAIに渡して、自然な文章で答えてもらう | Tool Callingの一連の流れ |
| **5. 必要なら発展** | 複数の機能呼び出し、送金前の確認などを検討する | より現実的な設計の判断 |

**いま取り組むのは段階1です。** いきなり全部を作る必要はありません。

## どこまでできたら、ひと区切り？

段階1では、次のことを自分で確認・説明できれば十分です。

- JSONを渡すと、残高照会や送金が動く
- おかしな要求なら、実行を拒否できる
- 送金に失敗したとき、どの口座の残高も変わらない
- なぜ、AIではなくアプリが実行可否を決めるのか説明できる

その後で本物のAIをつなぐと、「さっきまで手で書いていた要求を、今度はAIが作っている」と実感できるはずです。

---

### 覚えておきたいこと

> **AIは「この機能を使いたい」と提案する。アプリは「使ってよいか」を確かめ、実際に動かす。**

この役割分担がわかることが、このプロジェクトのいちばん大切な成果です。

細かい仕様やテスト条件が必要になったら、別の設計資料 [Tool Calling Bank Assistant.md](./Tool%20Calling%20Bank%20Assistant.md) を参照します。
