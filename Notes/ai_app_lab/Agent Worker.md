# Agent Worker

> **AIエージェントとツール実行を学ぶための独立した小さなアプリ**。全体方針は[README](README.md)を参照。

## 目的

ユーザーの依頼を受け、LLMが必要なツールを選んで情報を調べ、根拠とともに対応を**提案**する。ツール呼び出し・状態遷移・構造化出力・人間の承認・評価を実装して、単純なLLMチャットやRAGとの違いを理解する。

想定する案件知識：LLMエージェント、Function/Tool Calling、Pydanticによるスキーマ、安全なAPI実行、ワークフロー、Human-in-the-loop、エージェント評価。

## 中核ユースケース（固定）

**模擬システム障害の一次調査エージェント**。

ユーザーが「サービスAが遅い原因を調べて」と依頼する。

1. エージェントは許可されたツールから必要なものを選ぶ。
2. 事前に用意した模擬ログ、Metrics、デプロイ履歴をツール経由で読み取る。
3. 観測できた事実、原因候補、追加確認事項、対応案を構造化出力する。
4. **実際の変更・再起動・通知は実行しない**。人間が提案を確認・承認するところまでを作る。
5. 少量の模擬障害シナリオで、ツール選択と最終出力の品質を評価する。

## 最小アーキテクチャと責務

~~~text
依頼（CLI、必要なら後からAPI）
          |
          v
Haskell：Agent Loop / 状態 / ツール許可・実行 / 停止条件
          |
          +--> 模擬ログ取得ツール（読み取り専用）
          +--> 模擬Metrics取得ツール（読み取り専用）
          +--> 模擬デプロイ履歴ツール（読み取り専用）
          |
          v
Python：LLM呼び出し / Function Calling / Pydantic検証
          |
          v
構造化された調査報告・対応案 → 人間の確認
~~~

- **Haskell**: 制御ループ、ツールの登録と許可リスト、状態・履歴、実行回数の上限、結果の集約、承認待ちの表現、テストしやすい純粋ロジック。
- **Python**: LLMプロバイダーのTool Calling/構造化出力を扱い、Pydanticで入力・出力の形式を検証する。モデルやSDK固有部分を隔離する。
- 初期データは**固定のローカルfixture**。実システム、実運用アカウント、任意URL、任意コマンドには接続しない。
- 最初はモデル・SDKを一つ選ぶ。LangGraph/pydantic-ai等は比較したいときに追加し、導入自体を目的にしない。

## 最小の型・データの考え方

入力：依頼文・対象サービスID。

ツール要求：**許可されたtool名と検証可能な引数**。未知のツール、対象外のサービス、欠落・不正引数は拒否する。

ツール結果：成功データ、または区別可能な失敗。

最終結果：**観測事実 / 原因候補 / 根拠（どのツール結果か） / 推奨アクション / 不確実性 / 承認状態**。

会話文から直接shell文字列を生成して実行しない。LLMが出したツール要求は「実行命令」ではなく**検証対象の提案**。

## 段階と完成条件

### A1：最小のツール呼び出し（MVP）

- ローカルに模擬ログ/メトリクスを用意する。
- LLMが許可ツールを選択し、Haskellが検証・実行し、結果を再びLLMに渡す。
- ツールなしで回答可能なケースと、ツールが必要なケースを用意する。
- **完了**：一つの依頼について、どのツールをどの引数で何回呼んだかを追跡でき、最終報告が得られる。

### A2：安全なワークフローと構造化出力

- 複数ツール、回数上限、終了判定、API失敗、未知のツール、不正引数を扱う。
- Pydanticで調査報告のスキーマ検証。Haskellでも実行前の権限・引数を検証する。
- 対応案は**承認待ち**にし、承認・却下の記録をする。承認後も破壊的操作はしない。
- **完了**：失敗時にも無限ループせず、安全に終了できることを自動テストで確認する。

### A3：エージェント評価

- 5〜10件程度の模擬障害シナリオを用意する。
- 正しいツール選択、不要な呼び出し、根拠の正しさ、報告のスキーマ適合、タスク完了率を比較。
- **完了**：プロンプトやモデル変更の前後で評価結果を比較できる。

### A4：実サービスに近づける（任意）

- Python推論API、簡単な実行トレース・費用/遅延計測、失敗時再試行の境界を追加。
- 必要になった場合にだけ外部の**読み取り専用**APIを一つ連携し、明示的に許可を得る。
- **完了**：実行履歴と失敗原因を辿れ、安全なツール制約が維持されている。

## 今回は作らないもの

- 実サーバの再起動、クラウド設定変更、デプロイ、自動メール送信などの実行系エージェント。
- 任意のshell、ファイル書き換え、任意のWeb URLへのアクセス。危険なアクションは承認ありでも初期スコープ外。
- 万能パーソナルアシスタント、複数エージェントの会議・自律チーム、常時実行する監視サービス。
- 文書取り込み・Hybrid RAG（→ [[AI Support Desk]]）、画像検索（→ [[Visual Search Lab]]）。
- 永続チャットメモリ、複雑なUI、汎用エージェント基盤。

## 実装を始めるAIへの指示

- READMEとこのノートを確認し、**A1の障害一次調査**から開始する。題材を勝手に別の業務自動化へ置き換えない。
- Haskellがツールの実行可否・状態遷移を決定し、Pythonはモデル呼び出しに集中する。
- 機能追加より先に正常系・不正ツール・失敗・終了条件を確認する。外部接続やスコープ変更は利用者に相談し、同意後に記録する。
