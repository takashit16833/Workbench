# lem-project-workspace

## 目的

Lem で、Emacs の `project.el` とタブを組み合わせていた運用に近い作業環境を作る。

- 1プロジェクト = 1 Workspace
- Project の切り替えと Workspace の切り替えを連動させる
- 現在の Project に属するバッファだけを切り替え対象にする
- Project ルートを、その Workspace の作業基準ディレクトリとして扱う

Lem 標準の Project 機能と `frame-multiplexer` を再実装せず、薄くつなぐ拡張とする。

## 基本仕様

### Project と Workspace

登録済み Project を選択すると、対応する Workspace へ切り替える。

- 対応する Workspace がなければ作成する
- Workspace 名は Project 名を初期値とする
- 既に存在すれば新規作成せず、その Workspace へ移動する

イメージ:

```text
[ QuickTree ] [ RAGScope ] [ OtelLens ]
      ↑
   現在の Project / Workspace
```

### バッファ切り替え

Workspace 内では、現在の Project に属するバッファだけを候補にする。

```text
QuickTree Workspace
  ├─ tree.ts
  ├─ files.ts
  └─ extension.ts
```

他 Project のバッファは候補に出さない。

### ファイル検索

現在の Workspace に対応する Project ルートを基準に、Project 内のファイルを検索して開けるようにする。

### Workspace の作業基準ディレクトリ

各 Workspace は、対応する Project のルートを `project-root` として保持する。

この `project-root` を、その Workspace の論理的なカレントディレクトリとして扱う。

理由は、将来的に `.dir-locals.el` のような Project 固有設定・コマンドを持たせたとき、

```text
QuickTree Workspace
  → ~/QuickTree を基準に build / test / format

RAGScope Workspace
  → ~/RAGScope を基準に build / test / format
```

のように、Workspaceごとに正しい Project ルートでコマンドを実行したいため。

Lem の `change-directory` は `uiop:chdir` を使うため、OSのカレントディレクトリ自体はLem全体で共有される。
そのため Workspace ごとに別々のOS CWDを持たせるのではなく、コマンド実行時に Workspace の `project-root` を明示的な作業ディレクトリとして使用する。

## 想定コマンド

初期版では、次の程度に絞る。

- `project-workspace-switch`
  - Project を選択し、対応する Workspace へ移動する
- `project-workspace-switch-buffer`
  - 現在の Project に属するバッファだけから選択する
- `project-workspace-find-file`
  - 現在の Project 内のファイルを検索して開く

キーバインドは拡張側で固定せず、利用側の設定に任せる。

## 実装方針

利用するLem標準機能:

- Project
  - `saved-projects`
  - `find-root`
  - Project 内ファイル検索の仕組み
- Workspace
  - `frame-multiplexer` の作成・切り替え・名前変更
- Buffer
  - `buffer-list`
  - `buffer-directory`

Project管理やWorkspace管理そのものは独自実装しない。

## 配布

独立したLem拡張として作る。

```text
lem-project-workspace/
├── lem-project-workspace.asd
├── src/
└── README.md
```

まずは GitHub から `lem-extension-manager` で導入できる形にする。

将来的に安定したら Quicklisp への登録も検討する。

## 初期版ではやらないこと

- Workspace状態のセッション永続化
- Project管理機能そのものの再実装
- WorkspaceごとにOSレベルのCWDを分離すること
- Project固有コマンド定義の仕組みそのもの

Project固有コマンドは、Workspaceの `project-root` を利用できる土台までを初期版で用意する。
