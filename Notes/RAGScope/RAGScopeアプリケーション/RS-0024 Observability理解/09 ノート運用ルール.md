# ノート運用ルール

このフォルダは、RS-0024を理解・実装する間に参照するWorkbench上の作業ノートとして保守する。

現在何が正しいかは、RAGScope正本リポジトリの対象branch / commitにある実ファイルを優先する。このフォルダは正本ではない。

## 2種類に分ける

```text
00〜07
  = 現在実装を理解するためのノート
  = activeなRS-0024 branchのコードへ追従させる

08
  = 未実装の設計候補
  = 現在実装として読まない
  = 候補としてまだ生きているものだけを保守する
```

## 現在実装の確認先

依存・module構成を見たい場合:

```text
07 現在の静的依存マップ
    ↓
最終確認は ragscope.cabal / 実module
```

実行フローを見たい場合:

```text
03 Span実行フロー
04 exception伝播とEventRecord exactly-once
05 Trace Adapterコード読解
```

OpenTelemetry自体のProvider / Logger / Tracer等を見たい場合:

```text
01 OpenTelemetryの基本構造
```

## 古い設計ノートを別に残さない

実装前のドラフトや候補調査が現在実装と並んで残ると、どちらが現在状態なのか判別しづらくなる。

そのためRS-0024固有の旧ノートは、次のどちらかにする。

```text
現在理解に必要
  → 00〜07へ統合

未実装だが有用な設計候補
  → 08へ統合

それ以外
  → ActiveなNotesから削除
```

削除した情報はGit履歴から必要に応じて復元できる。Activeなノートへは、現在の理解または生きている設計候補として使う情報だけを置く。

## 更新するタイミング

少なくとも次の場合は関係するノートを更新する。

```text
ragscope.cabalのcomponent / build-depends / exposed-modulesが変わる
Telemetry moduleの追加・削除・import方向が変わる
Trace / Logsの公開Boundary型が変わる
Provider / Lifecycle / Metrics / Contextが実装される
exception処理の実装またはテスト期待値が変わる
MainのComposition Rootが実装される
```

候補を実装へ採用した場合は、08の候補を「現在実装」として残さず、該当する00〜07へ内容を移し、08側は削除または状態更新する。
