## 参考: Pythonサーバーのコード

コンテナ内で確認した。

```bash
docker exec -it ss-0001-api-1 bash
cat server.py
```

```python
import json
import os
from http.server import BaseHTTPRequestHandler, ThreadingHTTPServer


class Handler(BaseHTTPRequestHandler):
    def do_GET(self) -> None:
        if self.path == "/health":
            body = json.dumps({"status": "ok"}).encode()
            self.send_response(200)
            self.send_header("Content-Type", "application/json")
            self.send_header("Content-Length", str(len(body)))
            self.end_headers()
            self.wfile.write(body)
            return

        body = b"SadServers Lab SS-0001\n"
        self.send_response(200)
        self.send_header("Content-Type", "text/plain; charset=utf-8")
        self.send_header("Content-Length", str(len(body)))
        self.end_headers()
        self.wfile.write(body)

    def log_message(self, format: str, *args: object) -> None:
        print(f"http: {self.address_string()} - {format % args}", flush=True)


def main() -> None:
    host = os.environ.get("APP_HOST", "127.0.0.1")
    port = int(os.environ.get("APP_PORT", "8080"))
    print(f"starting api on {host}:{port}", flush=True)
    ThreadingHTTPServer((host, port), Handler).serve_forever()


if __name__ == "__main__":
    main()
```

## 仮説1: Webサーバーのプロセスが起動していないのでは？

### 検証

```bash
ps aux
```

```text
USER         PID %CPU %MEM    VSZ   RSS TTY      STAT START   TIME COMMAND
root           1  0.0  0.0    872   564 ?        Ss   Aug14   0:00 /sbin/docker-init -- python /app/server.py
root           7  0.0  0.2 106760 21692 ?        S    Aug14   0:00 python /app/server.py
root        1099  0.0  0.0   4164  3500 pts/0    Ss   00:04   0:00 bash
root        1695  0.0  0.0   6004  3272 pts/0    R+   00:08   0:00 ps aux
```

親子関係も確認する。

```bash
ps -eo pid,ppid,cmd
```

```text
    PID    PPID CMD
      1       0 /sbin/docker-init -- python /app/server.py
      7       1 python /app/server.py
   1099       0 bash
  13452    1099 ps -eo pid,ppid,cmd
```

### 結果

- `python /app/server.py` が PID 7 で存在している。
- PID 7 の PPID は 1 であり、PID 1 の `docker-init` の子プロセスとして動いている。

したがって、**「Webサーバーのプロセスが起動していない」という仮説は否定された。**

## 仮説2: PythonはTCPポートをLISTENしていないのでは？

### 検証

```bash
ss -lntp
```

```text
State    Recv-Q   Send-Q     Local Address:Port      Peer Address:Port   Process
LISTEN   0        5              127.0.0.1:8080           0.0.0.0:*       users:(("python",pid=7,fd=3))
LISTEN   0        4096          127.0.0.11:38599          0.0.0.0:*
```

さらに、コンテナ内からHTTPリクエストを送る。

```bash
curl http://localhost:8080/health
```

```text
{"status": "ok"}
```

### 結果

- PID 7 の Python は `127.0.0.1:8080` でTCP接続をLISTENしている。
- コンテナ内から `127.0.0.1:8080/health` へアクセスすると、正常なHTTPレスポンスが返る。

したがって、**「PythonがTCPポートをLISTENしていない」という仮説は否定された。**

この時点で分かっているのは、Pythonが **`127.0.0.1:8080` で待ち受けている**ということまで。

## 仮説3: PythonサーバーはDockerネットワーク側のIPでも接続を受け付けている？

まず、コンテナが持っているネットワークインターフェースとIPアドレスを確認する。

### 検証1: Dockerネットワーク側のIPを確認

```bash
ip addr
```

```text
1: lo: <LOOPBACK,UP,LOWER_UP> mtu 65536 qdisc noqueue state UNKNOWN group default qlen 1000
    link/loopback 00:00:00:00:00:00 brd 00:00:00:00:00:00
    inet 127.0.0.1/8 scope host lo
       valid_lft forever preferred_lft forever
    inet6 ::1/128 scope host proto kernel_lo
       valid_lft forever preferred_lft forever
2: eth0@if32: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc noqueue state UP group default
    link/ether 46:3a:8a:72:33:2d brd ff:ff:ff:ff:ff:ff link-netnsid 0
    inet 172.20.0.2/16 brd 172.20.255.255 scope global eth0
       valid_lft forever preferred_lft forever
```

### 検証1の結果

- loopbackインターフェース `lo` に `127.0.0.1` が割り当てられている。
- Dockerネットワーク側のインターフェース `eth0` に `172.20.0.2` が割り当てられている。

次に、Dockerネットワーク側のIPへ直接接続してみる。

### 検証2: `172.20.0.2:8080` へ接続

```bash
curl http://172.20.0.2:8080/health
```

```text
curl: (7) Failed to connect to 172.20.0.2 port 8080 after 0 ms: Could not connect to server
```

### 結果

**`172.20.0.2:8080` では接続を受け付けていない。**

ここで仮説3の検証は終了。

## 現在地

ここまでで確認できた事実は次の3点。

1. Pythonサーバーのプロセスは起動している。
2. Pythonは `127.0.0.1:8080` でLISTENしており、コンテナ内からのHTTPアクセスは成功する。
3. Dockerネットワーク側のIP `172.20.0.2:8080` への接続は失敗する。

**まだ原因確定や修正には進んでいない。**

次の調査では、この3つの観測をもとに新しい仮説を立てる。
