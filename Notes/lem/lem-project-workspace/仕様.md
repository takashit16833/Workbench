# lem-project-workspace

## 目的

Lem のグローバルなバッファ管理と `frame-multiplexer` を組み合わせ、Emacs で行っていた「プロジェクトや用途ごとにタブを分け、そのタブ内のバッファだけを扱う」運用を実現する。

Project 管理、Buffer 管理、`frame-multiplexer` 自体は再実装しない。

この拡張が提供する中心的な能力は次の2つとする。

1. Frame Routing
2. Frame Buffer List

## 1. Frame Routing

Buffer / File の情報から route を決定し、対応する `frame-multiplexer` へ振り分ける。

route は frame の識別情報として使用する。

例:

```text
(:project ~/QuickTree/)  -> QuickTree
(:project ~/RAGScope/)   -> RAGScope
:misc                    -> Misc
```

同じ route の frame が既に存在すればその frame を使用し、存在しなければ新しく作成する。

### Routing Filter

ルーティング規則は routing engine 本体へ直接書かず、フィルタ関数として外出しする。

各フィルタは上から順に評価し、最初に route を返したものを採用する。

概念:

```lisp
(defvar *routing-filters*
  (list #'project-routing-filter))

(defun resolve-route (buffer)
  (or (some (lambda (filter)
              (funcall filter buffer))
            *routing-filters*)
      :misc))
```

フィルタの契約:

```text
入力:
  Buffer またはそのファイル情報

出力:
  route
  または nil
```

標準では Project 用フィルタを提供する。

```text
Project に所属する
  -> (:project project-root)

どのフィルタにも一致しない
  -> :misc
```

利用者はフィルタを追加することで、Routing 本体を変更せずに独自の分類を追加できる。

例:

```text
Workbench tasks -> :tasks
Org file        -> :org
Project file    -> (:project project-root)
その他          -> :misc
```

## 2. Frame Buffer List

Lem の `buffer-list` 自体はグローバルのままとする。

frame ごとに独自のバッファ集合を保持するのではなく、各 Buffer の route を計算し、現在の frame の route と一致する Buffer だけを抽出する。

```text
global buffer-list
        |
        | resolve-route
        v
+--------------------------+
| (:project ~/QuickTree/)  | -> QuickTree frame
| (:project ~/RAGScope/)   | -> RAGScope frame
| :misc                    | -> Misc frame
+--------------------------+
```

概念:

```text
frame-buffer-list(frame)
  = global buffer-list
    を
    resolve-route(buffer) == frame-route(frame)
    で絞り込んだ結果
```

これにより、Buffer の所属状態を別途管理せず、Routing 規則を唯一の判定基準として利用する。

## Project Route

Project 用フィルタは Lem 標準の Project 判定を利用し、Project root を route に含める。

```text
buffer
  -> buffer-directory
  -> find-root
  -> (:project project-root)
```

Project root は route の一部であり、別途 Virtual Root のような状態は持たない。

必要な機能は現在の frame の route から Project root を取得できる。

```text
current frame
  -> (:project ~/QuickTree/)
  -> ~/QuickTree/
```

そのため、将来的に Project 固有の build / test / format などを実行する場合も、この route に含まれる Project root を作業基準として利用できる。

## Misc

どの Routing Filter にも一致しない Buffer / File は `:misc` に所属させる。

起動時には Misc frame を用意し、野良ファイルや Project に所属しない Buffer の受け皿とする。

例:

```text
~/tmp/test.txt -> Misc
*scratch*      -> Misc
```

特殊 Buffer の扱いは必要に応じて Routing Filter で拡張する。

## 設計原則

- Lem 標準の Project 管理を再実装しない
- Lem 標準のグローバル `buffer-list` を変更しない
- `frame-multiplexer` 自体を再実装しない
- Buffer の所属情報を二重管理しない
- Routing 規則はフィルタ関数として追加できるようにする
- Routing engine は Project など具体的な分類を知らない
- Project root は Project route に含め、別の Virtual Root 状態を持たない

## 初期版

初期版では次を実装対象とする。

- route を frame-multiplexer に保持する
- Routing Filter の登録と評価
- Project Routing Filter
- Misc fallback
- route に対応する frame の検索・作成・切り替え
- 現在 frame の route に基づく Buffer List の絞り込み

キーバインドは拡張側で固定せず、利用側の設定に任せる。

## 配布

独立した Lem 拡張として作る。

```text

├── lem-project-workspace.asd
├── src/
└── README.md
```
