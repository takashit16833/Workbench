# lem-project-workspace

## 目的

Lem のグローバルなバッファ管理と `frame-multiplexer` を組み合わせ、Emacs で行っていた「プロジェクトや用途ごとにタブを分け、そのタブ内のバッファだけを扱う」運用を実現する。

Project 管理、Buffer 管理、`frame-multiplexer` 自体は再実装しない。

この拡張が提供する中心的な能力は次の2つとする。

1. Frame Routing
2. Frame Buffer List

## 1. Frame Routing

Buffer / File の情報から routing destination を決定し、対応する `frame-multiplexer` へ振り分ける。

例:

```text
(:project ~/QuickTree/)  -> QuickTree frame
(:project ~/RAGScope/)   -> RAGScope frame
:misc                    -> Misc frame
```

destination は frame 自身へ埋め込む必要はない。

Router が次の対応関係を管理する。

```text
destination <-> frame-multiplexer
```

同じ destination に対応する frame が既に存在すればその frame を使用し、存在しなければ新しく作成する。

### Routing Filter

ルーティング規則は routing engine 本体へ直接書かず、フィルタ関数として外出しする。

各フィルタは上から順に評価し、最初に destination を返したものを採用する。

概念:

```lisp
(defvar *routing-filters*
  (list #'project-routing-filter))

(defun resolve-destination (buffer)
  (some (lambda (filter)
          (funcall filter buffer))
        *routing-filters*))
```

フィルタの契約:

```text
入力:
  Buffer またはそのファイル情報

出力:
  destination
  または nil
```

routing engine は Project など具体的な分類を知らない。

利用者はフィルタを追加することで、routing engine 本体を変更せずに独自の分類を追加できる。

例:

```text
Workbench tasks -> :tasks
Org file        -> :org
Project file    -> (:project project-root)
野良 file       -> :misc
```

### Project Routing Filter

標準では Project 用フィルタを提供する。

Project 判定には Lem 標準の Project 機能を利用する。

```text
buffer / file
  -> directory
  -> find-root
  -> (:project project-root)
```

Project root は Project destination 自体に含める。

別途 Virtual Root のような状態は持たない。

必要な場合は destination から Project root を取得する。

```text
(:project ~/QuickTree/)
  -> ~/QuickTree/
```

そのため、将来的に Project 固有の build / test / format などを実行する場合も、この Project root を作業基準として利用できる。

### Misc

Project などの Routing Filter に一致しない「ルーティング対象のファイル」は `:misc` に振り分ける。

例:

```text
~/tmp/test.txt -> :misc
```

起動時には Misc frame を用意し、Project に所属しない野良ファイルの受け皿とする。

一方、すべての特殊 Buffer を必ず Misc へ送るわけではない。

```text
*scratch*
*Help*
REPL
一時表示用 Buffer
```

など、通常のファイルルーティング対象ではない Buffer は destination を `nil` とし、現在の frame に残すことを許容する。

特殊 Buffer を特定の frame へ送りたい場合は、利用者が Routing Filter を追加できるようにする。

### Routing の適用範囲

Lem の Buffer 表示には複数の経路があるため、すべての Window への表示を強制的に Routing することは目的としない。

通常の編集 Buffer の切り替えを Routing 対象とする。

Lem の `switch-to-buffer` には `*switch-to-buffer-hook*` があり、`pop-to-buffer` も通常は内部で `switch-to-buffer` を使用するため、これを主な差し込み口とする。

ただし Lem には、Side Window などが低レベルに Buffer を直接設定する経路もある。

これらは無理に捕捉しない。

特に次のような補助 Window は、通常は Routing 対象外とする。

- Side Window
- Floating Window
- Attached Window
- Header Window
- Prompt や Help などの一時表示

目的は「あらゆる Buffer 表示を捕捉すること」ではなく、「通常の編集コンテキストを適切な frame-multiplexer へ振り分けること」とする。

## 2. Frame Buffer List

Lem の `buffer-list` 自体はグローバルのままとする。

frame ごとに独自の Buffer 集合を保持しない。

Router が持つ

```text
destination <-> frame-multiplexer
```

の対応関係を利用し、対象 frame の destination を逆引きする。

その destination と、各 Buffer に Routing Filter を適用した結果が一致する Buffer だけを抽出する。

```text
current frame
    |
    | Router を逆引き
    v
destination
    |
    | global buffer-list を filter
    v
frame-local buffer list
```

概念:

```text
frame-buffer-list(frame)
  = global buffer-list
    を
    resolve-destination(buffer) == destination-of(frame)
    で絞り込んだ結果
```

Buffer の所属状態は別途保存しない。

Routing 規則と Router の対応関係を唯一の判定基準として利用する。

## 設計原則

- Lem 標準の Project 管理を再実装しない
- Lem 標準のグローバル `buffer-list` を変更しない
- `frame-multiplexer` 自体を再実装しない
- Buffer の所属情報を二重管理しない
- destination を frame 自身へ埋め込むことを前提にしない
- Router が `destination <-> frame-multiplexer` の対応を管理する
- Routing 規則はフィルタ関数として追加できるようにする
- Routing engine は Project など具体的な分類を知らない
- Project root は Project destination に含め、別の Virtual Root 状態を持たない
- すべての Window 表示を無理に捕捉せず、通常の編集 Buffer の Routing に責務を絞る

## 初期版

初期版では次を実装対象とする。

- Routing Filter の登録と評価
- Project Routing Filter
- 野良ファイルの Misc fallback
- Router による `destination <-> frame-multiplexer` の対応管理
- destination に対応する frame の検索・作成・切り替え
- 通常の Buffer 切り替えに対する Routing
- 対象外の特殊 Buffer / 補助 Window を現在の frame に残す
- Router の対応関係と Routing Filter に基づく Frame Buffer List の絞り込み

キーバインドは拡張側で固定せず、利用側の設定に任せる。

## 配布

独立した Lem 拡張として作る。

```text
lem-project-workspace/
├── lem-project-workspace.asd
├── src/
└── README.md
```

まずは GitHub から `lem-extension-manager` で導入できる形にする。
