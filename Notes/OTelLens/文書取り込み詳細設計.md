# 文書取り込み詳細設計

## 処理の流れ

```mermaid
flowchart LR
    PATH --> A[対象ファイル列挙]
    A --> B[文書読み込み]
    B --> C[文書分割]
    C --> D[Embedding生成]
    D --> E[PostgreSQL保存]
```

## 対象ファイル列挙

- PATHがディレクトリでない場合は失敗する。
- PATH配下を再帰的に走査し、拡張子が `.md` の通常ファイルを列挙する。
- 対象ファイルが1件もない場合は失敗する。

## 文書読み込み

列挙したファイルを読み込む。  
読み込みに失敗した場合は取り込み全体を失敗する。

## 文書分割

MarkdownをCommonMarkとして解析し、見出しを境界として文書を分割する。

1つの見出しから次の見出しの直前までを1つの文書断片とする。  
見出しがある文書断片は、見出し文字列と本文を空行1つで連結した文字列を内容とする。

文書先頭から最初の見出しまでに本文がある場合は、その本文を1つの文書断片とする。  
見出しがない文書は、文書全体を1つの文書断片とする。

## Embedding生成

Pythonでは `sentence-transformers` を使用し、`jinaai/jina-embeddings-v2-small-en` でEmbeddingを生成する。  
Embeddingの次元数は512、入力上限は8192トークンとする。

モデル読み込みではモデル固有コードの読み込みを有効にする。

Haskellは `process` パッケージを使い、次のPythonプログラムをOSの子プロセスとして実行する。

```text
python3 python/embedding.py
```

全ての文書断片を1回のJSONリクエストで標準入力へ渡し、Embeddingを標準出力から受け取る。

### 入力

| 項目 | 内容 |
| --- | --- |
| texts | 文書断片の文字列の配列 |

### 出力

| 項目 | 内容 |
| --- | --- |
| embeddings | Embeddingの配列 |

`embeddings` は `texts` と同じ件数・同じ順序で返す。  
各Embeddingは512要素とする。

8192トークンを超える文書断片がある場合はEmbedding生成を失敗する。  
Pythonが異常終了した場合、JSONを読み取れない場合、件数または次元数が一致しない場合も失敗する。

## PostgreSQL保存

接続先は環境変数 `DATABASE_URL` から取得する。

保存先は `document_chunks` テーブルとする。

| カラム | 型 | 内容 |
| --- | --- | --- |
| id | bigserial | 主キー |
| content | text | 文書断片 |
| embedding | vector(512) | 文書断片のEmbedding |

`vector` 型にはpgvectorを使用する。

Embedding生成が全件成功した後、1つのトランザクションで次の順に処理する。

```mermaid
flowchart LR
    BEGIN --> A["document_chunksを全削除"]
    A --> B[今回の文書断片を保存]
    B --> COMMIT
```

保存に失敗した場合はロールバックする。

## 終了

成功時は、取り込み完了と文書数・文書断片数を標準出力へ表示し、終了コード0とする。

失敗時は、原因を標準エラー出力へ表示し、終了コード1とする。
